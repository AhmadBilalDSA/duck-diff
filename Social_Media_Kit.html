2LinkedIn — Long-form (production-grade positioning)

🦆 Announcing duck-diff: production-grade data diffing for teams whose pipelines can't afford surprises.

Every data team knows the moment: a dashboard looks wrong, someone asks "did the upstream change?", and three engineers lose a day finding out. duck-diff answers that question in seconds — deterministically, inside CI.

WHAT IT DOES
Diff any two datasets — Parquet, CSV, TSV, JSON/JSONL/NDJSON, or SQLite tables — and report precisely:

→ Schema drift: columns added or removed, type changes detected via metadata-only inspection
→ Row-level drift: additions and deletions matched on a composite primary key (--key id,region)
→ Cell-level drift: per-column mismatch counts and drift percentages, plus sample records showing old vs new values side-by-side

WHY IT'S DIFFERENT
Most diff tools load both datasets into RAM. At scale, that's a crash waiting to happen. duck-diff compiles the entire comparison into DuckDB SQL — null-safe full outer joins, set algebra, hash aggregation — and streams results. Memory stays flat whether you diff megabytes or gigabytes, and you can cap it explicitly with --memory-limit.

BUILT FOR REAL DATA (the part most tools skip)
• NULL semantics done right: NULL equals NULL; empty string ≠ NULL
• Floating-point tolerance: --epsilon treats numerically-equal values as matches without weakening key matching
• No primary key? Keyless mode hashes whole rows with correct duplicate-row (multiset) accounting
• Case-insensitive comparison mode for inconsistent sources
• Robust CSV ingestion that survives mixed line endings and ragged files
• Clear exit-code contract: 0 = clean, 1 = drift, 2 = error — trivially scriptable

CI/CD READY
Ships as a turnkey GitHub Action. Five inputs (source_path, target_path, key_columns, epsilon, fail_on_drift), three outputs (drift_detected, modified_rows, schema_drift) you can branch on, and a Markdown report with drift badges designed to be pasted directly into pull requests. Schema drift alone can fail a build — because a new column IS a contract change.

FOR DEVELOPERS
Clean Python API in three lines:

    from duck_diff import diff
    result = diff("baseline.parquet", "candidate.parquet", keys=["id"])
    print(result.summary.column_drift_stats)

Fully typed (py.typed included), Rich terminal UI with graceful ASCII fallback, JSON output for machines, MIT licensed, and a 42-test suite that runs completely offline.

Data quality shouldn't be a postmortem. Make it a gate. 🚪

Title:
I open-sourced duck-diff: constant-memory dataset diffing (Parquet/CSV/JSON/SQLite) via embedded DuckDB, with a GitHub Action that gates PRs on data drift
Body:
After one too many "silent" upstream changes breaking downstream models, I built the tool I kept wishing existed.

What it gives you in one command:
- Schema drift (columns/types) — detected metadata-only, costs nothing
- Row additions/deletions keyed on composite PKs (--key id,region)
- Cell-level drift stats per column (mismatch count + drift %)
- Top-N sample mismatches: [key, column, value_before, value_after]

Design choices you may care about:
- Everything executes INSIDE DuckDB (full outer joins + set algebra). Nothing is loaded into pandas/RAM. Constant memory, optional --memory-limit cap.
- Null-safe equality everywhere (IS NOT DISTINCT FROM). NULL==NULL matches; NULL vs '' is drift. This matters more than people think.
- --epsilon for float noise (TRY_CAST-based, applied to values, never to join keys).
- Keyless mode: MD5(CONCAT_WS('||', ...)) row hashing with proper multiset counting, so duplicate rows don't lie to you.
- Sources: parquet/csv/tsv/json/jsonl/ndjson paths + sqlite://db#table URIs, auto-detected.
- Output formats: Rich terminal (ASCII fallback if rich isn't installed), GFM markdown with shields badges + collapsible sections for PR comments, and JSON for assertions.
- GitHub Action included: inputs source_path/target_path/key_columns/epsilon/fail_on_drift; outputs drift_detected/modified_rows/schema_drift. fail_on_drift makes CI exit 1 on any drift (schema drift counts).
- Exit code contract: 0 clean / 1 drift / 2 usage-or-runtime error.

Stack: pure Python 3.9+, single hard dependency (duckdb>=0.10). Typer CLI when available, argparse otherwise. Fully type-hinted, py.typed shipped. MIT.

Test suite: 42 tests, 100% offline — generates its own CSV/TSV/JSON/Parquet/SQLite fixtures, covers NULL semantics, epsilon boundaries, keyless multisets, CLI exit codes, and the Action's output contract.

Repo layout is small on purpose: io.py (loaders), schema_diff.py, engine.py (DuckDiffer), reporter.py, cli.py, action.py.

Happy to answer questions about the SQL algebra (null-safe joins + row-number sentinels for presence detection) or the CI setup. What would you want added — snapshot storage? Delta/Iceberg readers? Slack webhook output?

6Changelog-style notes (blog / newsletter)

## duck-diff v1.0.0 — release highlights

### Core engine
- Keyed diffing on composite keys (--key id,region) using NULL-safe FULL OUTER JOINs
- Keyless diffing via MD5 row hashing with exact multiset semantics under duplicates
- Per-column drift statistics: mismatch count + drift percentage
- Top-N sample mismatch records [key, column, value_a, value_b]
- Epsilon float tolerance (--epsilon) — TRY_CAST-based, never relaxes key joins
- Case-insensitive text comparison (--ignore-case)
- Constant-memory execution; optional DuckDB buffer cap (--memory-limit 2GB)

### Sources & schema
- Auto-detected loaders: .parquet, .csv, .tsv, .json/.jsonl/.ndjson, sqlite://<db>#<table>
- Native SQLite attach with automatic chunked stdlib-sqlite3 fallback (air-gap friendly)
- Metadata-only schema drift: columns only-in-A / only-in-B, type mismatch strings
- Lenient CSV retry (strict_mode=false) for ragged/mixed-EOL files

### Interfaces
- CLI flags: --key --epsilon --ignore-case --format table|markdown|json --output --limit --fail-on-drift --memory-limit
- Typer-powered UX with automatic argparse fallback
- Python API: diff(...) one-liner + reusable DuckDiffer context manager; fully typed (py.typed)
- Reporters: Rich cards/tables (ASCII fallback), GitHub-flavored Markdown with shields.io badges and collapsible sections, stable JSON document

### CI/CD
- Composite GitHub Action: inputs source_path, target_path, key_columns, epsilon, fail_on_drift; outputs drift_detected, modified_rows, schema_drift
- Strict gating contract: exit 0 = clean, 1 = drift detected, 2 = error
- Unicode-safe console output on legacy Windows codepages

### Quality
- 42 offline tests: NULL semantics, epsilon boundaries, keyless multisets, CLI exit codes, Action output contract, reporters
- Single runtime dependency: duckdb>=0.10.0; extras: [ui], [dev]
- MIT licensed
